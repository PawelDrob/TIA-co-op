## 1. Reading the tables

- **Display name and group** are TIA's, from its Properties window in the table view, sorted by group and name as TIA sorts them. A name in *italics* is the export name: the row was not in a screenshot, or is not in the Properties window (`TabIndex`). A name ending in "..." was cut off in the screenshot; "(inferred)": it was cut off and is completed from the same ending seen whole on another row ("(border)", "(layout)", "(appearance)").
- **Export name**: the element in the SimaticML `AttributeList`; `@Name` an `ObjectList` member (`MultilingualText` or `MultiLingualFont`) with that `CompositionName`; `link:Name` a `LinkList` entry; `tag:Name` a `Properties` entry with a tag connection; `-` a row TIA shows that the export does not carry. A link or tag name marked "not seen" was not in an export yet.
- **Default**: the value of the object as dropped from the toolbox, device style WinCC Dark, in the export's spelling; TIA's text for it in brackets where it differs ("Round" is shown "Flush"). The defaults are a reference only: a project's objects follow its own style presets.
- **Values** of an enum: the spellings confirmed by an export or by the spelling round trip (a zz test screen with the value set, imported and exported again; they import), then the values TIA's help documents that nothing has confirmed yet, in their export spelling: the member of TIA's own enum type for the attribute (named last, read from TIA's HMI library) of the same name, or of the same number, with the help's name and number in brackets ("not in TIA's enum": no member, TIA cannot read it). Values the round trip sent and TIA did not keep are listed as lost. The HMI preview's validator passes a confirmed value, warns on a documented one or another member of the enum (TIA may refuse it at import) and refuses anything else.
- **Greyed** when: the conditions under which TIA greys the row, where known (seen in several screenshots, obvious, or from the help's mode table where the screenshots agree).
- **Openness**: the 20 basic objects and elements and the user view go through Openness (export and import). The other 14 controls are left out of the export silently ([WinCC guide](wincc-comfort-openness.md) 7.1): build them by hand in TIA; their properties come from the help only, without defaults or display names.

## 3. The data file

`TiaHmiGenerator\catalogue\catalogue.json`, schema 1. Read it with `hmipreview.catalogue` (`load()`, `by_element()`, `attribute()`, `attribute_names()`, `enum_members()`, `fixture_objects()`). Top level: `schema`, `tia`, `style`, `sources`, `types` (the objects above, in this order), `parts` (element types below the objects: fonts, texts, animations, events, properties, with their attributes and confirmed values; those without attributes empty), `enums` (TIA's enum types the attributes name: member -> number).

A type: `key` (element without `Hmi.Screen.`, null for a control whose element is unknown), `element`, `toolbox` {`group`, `name`}, `stem` (TIA's default ObjectName without `_1`), `openness`, `source` (fixture | exports | help), `purpose`, `help` {`object`, `vbsType`}, `attributes`, `links`, `events` and `animations` (seen in exports), `preview` {`state`, `drawn`, `notDrawn`, `note`}.

An attribute: `name` (export name, `@Composition`, `link:Name`, `tag:Name`, or null for a row the export does not carry, then `export` false), `display`, `displayKnown` (true; "cut": cut off in the screenshot, kept with "..."; "inferred": cut off and completed; false: the export name), `group` (TIA's, null when not in the Properties window), `kind` (colour | bool | number | enum | text | list | blob | font | link | tag), `default` (export spelling; fonts as "Tahoma, 13px, style=Bold"), `shown` (TIA's text for the default when it differs), `values` {`confirmed` (seen in an export, the fixture or the round trip), `documented` [{`value`, `constant`, `name`, `spelling` (the export spelling from TIA's enum, null: no member; only with `enum`), `confirmed`, `spellingSeen`}], `range`, `enum` (TIA's enum type), `lost` {sent: exported}}, `description`, `access` {`professional`, `advanced`, `panel`: R | RW | -} (runtime access per the help), `greyedWhen` [{`attribute`, `op` eq | ne | in, `values`} or {`always`}; any one greys], `modes` (the help's mode table), `unsure` (the display row may belong to another attribute), `nameSeen` false (a link or tag name not seen in an export).

## 4. Rebuilding

From `TiaHmiGenerator`, with `<py>` = `<tool repo>\.venv\Scripts\python.exe -X utf8`: `<py> catalogue\build.py` rebuilds `catalogue.json` and this page from the committed inputs; `--check` fails when they are not current (a unit test runs it). Inputs: `toolbox.json` (by hand: display names, groups and order from TIA's Properties window, greyed-row conditions, descriptions in our own words, the preview's coverage, `enumTypes`: the enum type of each enum attribute), `fixture\` (full exports of the test screens, every toolbox object dropped unchanged; `hmixml` copies a type no project export holds from it: `blank`, `shape_item`), `helpfacts.json` (facts read from TIA's installed help: `--help-zip <Help\en-US\VBSObjectsWCCCenUS.zip>`; names, access, constants and ranges, never help text), `seen.json` (enum spellings, links, events and animations seen in full exports: `--seen <project repo>`, repeatable; names and spellings only), `enums.json` (TIA's enum types of the screen objects, member names and numbers, by reflection from its HMI library: `--enums <Bin\Siemens.Simatic.Hmi.Global.dll>`; Windows PowerShell, TIA is not started) and `roundtrip\` (the spelling round trip).

The spelling round trip: `<py> catalogue\roundtrip.py <folder>` writes the test screens `zzTestSpellings.xml` and `zzTestSpellings2.xml` (objects copied from the fixture, one documented spelling not yet confirmed per object, with the dependent properties the table expects; values taken as not allowed on Comfort panels left out, those one panel may not allow on the second screen; dependent properties and device refusals from `dependent.json`, which the validator reads as well) and `roundtrip\sent.json`. Import each screen into a project, export it again, put the exports into `roundtrip\back\` without their `InstalledProducts`, and rebuild: a value that came back is confirmed, one that came back different is lost. Only the coordinator's bridge touches TIA.

A new TIA version: export the two test screens again (every toolbox object dropped, full export), replace the fixture (strip the device, project and tag names), take new screenshots where the Properties window changed, run the build with `--help-zip`, `--enums` and `--seen`, read the problems it prints (screenshot values that differ from the export defaults, rows without an export attribute, confirmed spellings that are no member of the enum named), and run the round trip again.
