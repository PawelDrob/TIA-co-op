# Rationales

* [ADR 0001: The skills' config in docs/agents/, beside the guides in docs/agent/](0001-skills-config-beside-the-guides.md) - The engineering skills' config stays in docs/agents/ although its name is one letter from the guides' folder docs/agent/, because the setup skill looks for that name and the guides' path is named throughout the bridge.
* [ADR 0002: The bridge is registered per user, not by a tracked .mcp.json or a plugin](0002-bridge-registered-per-user.md) - The MCP server is added per user with claude mcp add, and per folder for a second clone, because a plugin or project server can start a second bridge or fail by the folder it starts from, and a second bridge can hang TIA.
* [ADR 0003: The skills plugin is enabled by its official marketplace id](0003-skills-plugin-from-the-official-marketplace.md) - The tracked settings name mattpocock-skills@claude-plugins-official, at the cost of a marketplace and an install command in first setup, because a second id for the same plugin gives everyone already on the official route every skill twice.
* [ADR 0004: The TIA dashboard starts a report run; the run does the work through the bridge](0004-the-tia-dashboard-starts-a-report-run.md) - The TIA dashboard's one button starts a separate process that runs TiaBridge in a report-run mode to export, commit and report, so the page stays a reader, the export is the bridge's own, and an agent's bridge and the run keep off each other's TIA.
